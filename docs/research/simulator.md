# Модель генератора эксперимента, версия 1

Генератор создаёт синтетические входные данные для исследования корреляции алертов.
Он не запускает корреляторы, не вычисляет метрики и не содержит метода корреляции.
Термин «корень» здесь означает заданный при генерации сервис отказа, то есть истину,
а не предполагаемый корень, найденный методом.

## Изоляция и запуск

Код находится в `src/experiment/java`, ресурсы — в `src/experiment/resources`.
Gradle source set `experiment` имеет собственный classpath: JDK, выход `main`
для чистых типов и Jackson для адаптера JSON. Ядро `experiment.graph` и
`experiment.scenario` не зависит от Spring, JPA и Jackson. Из продуктовых пакетов
разрешены только чистые типы `alert.correlation` и enum домена. Это проверяет
`ExperimentIsolationTest`. Продукт не зависит от эксперимента; `check` также
проверяет отсутствие его классов и ресурсов в bootJar. Экспериментальных бинов нет.

Запуск без HTTP-сервера, Spring-контекста и БД:

```powershell
./gradlew.bat generateExperiment
./gradlew.bat generateExperiment --args="--config src/experiment/resources/experiment/configs/tree.json --output build/experiments/tree.json"
```

Без аргументов используются `ExperimentDefaults` и файл
`build/experiments/scenario.json`. Аргументы `--config FILE` и `--output FILE`
независимы. Все выходные файлы должны лежать внутри `build/experiments/`.
Конфигурации demo, tree, layered, diamonds, cyclic содержат все параметры;
неизвестные и отсутствующие обязательные поля отвергаются.

## Истинный граф

`ServiceGraph = (V, E)`: вершина `(id, code, name, tier)`, дуга
`(dependentId, dependencyId, type)` направлена «зависимый → зависимость».
Граф неизменяем, непуст; идентификаторы положительны, коды уникальны.
Петли, повторные пары концов даже с другим типом и ссылки на отсутствующие
вершины запрещены. Произвольный входной граф может быть несвязным.
Генераторы создают слабо связные графы. Синтетические вершины имеют коды
`SERVICE_1` … `SERVICE_n`, одинаковый заданный tier и заданный тип дуги.
Привязка последовательных id к позициям топологии перемешивается по seed графа.
Для регулярных деревьев и ромбов seed меняет именно эту привязку.

* Дерево: глубина D — число дуг от корня до листа; ветвление B — число детей
  каждой внутренней вершины. Дети зависят от родителя. D ≥ 0, B ≥ 1;
  |V| = Σ(B^i), i = 0…D, |E| = |V| − 1.
* Слоистый DAG: L слоёв ширины W, дуги только из слоя i в i−1.
  Число допустимых дуг C = (L−1)W²; целевое число M = round(density × C).
  Сначала строится связный остов: на первой границе выбираются по одной
  опорной вершине с каждой стороны, соединяются со всеми вершинами другой
  стороны (2W−1 дуг). Каждая вершина следующего слоя получает одну случайную
  зависимость из предыдущего. Оставшиеся допустимые пары перемешиваются
  и выбираются без возвращения до M. Требуется M ≥ LW−1.
  L, W ≥ 1; при L = 1 допустима только W = 1. Плотность в [0,1].
  Это выборка с принудительной связностью, а не независимые испытания Бернулли.
* Ромбы: K последовательно соединённых ромбов. Каждый — две внутренне
  непересекающиеся ветви по H дуг с общими концами. K ≥ 1, H ≥ 2;
  |V| = 1 + K(2H−1), |E| = 2KH. Конец одного ромба — начало следующего.
* Циклический граф: слоистый DAG с L ≥ 2, затем для
  max(1, round(reverseEdgeRate × M)) случайных дуг добавляются обратные.
  Доля в (0,1], поэтому цикл гарантирован даже при малом M.
  Доля считается относительно исходного DAG, не итогового числа дуг.
* Демо: зафиксированная копия 10 услуг и 10 зависимостей V7 в
  `experiment/graphs/demo-v1.json`. Идентификаторы локальны и назначены
  по коду услуги. Интеграционный тест сравнивает с БД коды, имена, tier,
  концы и типы дуг, независимо от последовательностей id БД.

## Наблюдаемый граф

`GraphDistortion(missingEdgeRate, spuriousEdgeRate, seed)` не меняет вершины.
При M = |E| истинного графа удаляется ровно round(missingEdgeRate × M)
случайных дуг без возвращения. Добавляется ровно round(spuriousEdgeRate × M)
дуг из дополнения **исходного истинного** графа, без петель и повторений.
Обе доли в [0,1] и обе считаются от M. При нехватке дополнения — ошибка
параметров, а не уменьшение числа добавлений. Удалённые истинные дуги не
возвращаются как ложные. Тип добавляемой дуги задаётся `spuriousEdgeType`.
Наблюдаемый граф может потерять связность или получить циклы.
Распространение отказов всегда использует истинный граф. Изменение искажения
не меняет ни поток алертов, ни разметку; это закреплено тестом.

## Отказы и распространение

Период инъекций — полуинтервал [start, start + injectionPeriod).
Начала всех отказов и шум находятся внутри него; поздние алерты отказа
не отбрасываются. Начало задаётся UTC Instant, а не системными часами.
Времена и длительности кратны миллисекунде, длительности неотрицательны.

`FailurePlan.Explicit` задаёт `(id, rootServiceId, startedAt)` каждого отказа;
id уникальны, повторный корневой сервис разрешён. Пустой список даёт только шум.
`Selected` задаёт count, firstStartOffset и spacing; отказ i начинается
в start + firstStartOffset + i × spacing, получает id F1, F2, ….
Все выбранные корни различны. Режим `UNIFORM_DISTINCT` выбирает их равномерно
без возвращения. В `PATH_CONNECTED_TO_FIRST` между первым и каждым следующим
корнем существует направленный путь хотя бы в одну сторону в истинном графе.
Сначала равномерно выбирается первый из корней с достаточным числом таких
сервисов, затем остальные — из их перемешанного списка. Общего предка или
неориентированной связности недостаточно. Невыполнимый запрос — ошибка.
«Независимые» означает самостоятельные инъекции, а не топологическую несвязность.

Для каждого отказа каждая истинная дуга независимо открывается с вероятностью p.
В каноническом порядке дуг выбираются испытание и задержка передачи (также
для закрытых и недостижимых дуг, чтобы порядок потребления RNG был явным).
Отказ движется от зависимости к зависимому по открытым дугам. Время активации
сервиса — минимум суммарных задержек путей от корня плюс момент начала отказа.
Корень активируется всегда. Циклы и несколько путей не создают повторных
активаций; нулевые задержки допустимы.

Каждый активированный сервис порождает один алерт на каждый отказ:
occurredAt = activationTime + detectionDelay(service).
Задержка обнаружения выбирается независимо для каждой пары сервис–отказ;
`detection.defaultDistribution` используется, если для id нет override.
Типы распределений: `FIXED(value)` и дискретное равномерное
`UNIFORM(minimum, maximum)` с включёнными границами в миллисекундах.
При разбросе обнаружения зависимый сервис может выдать алерт раньше корня;
тест перебирает воспроизводимый набор seed и проверяет это свойство.

При пересечении отказов общий сервис выдаёт отдельный алерт для каждого,
с собственной меткой отказа и задержкой обнаружения. Подавления, дедупликации
и объединения сигналов разных отказов нет.

## Сигналы и шум

Модель `SignalModel` задаёт три отдельных `SignalDistribution`: root,
propagated, noise. В каждом независимо выбираются тип и severity по
спискам положительных целочисленных весов; пропущенный enum имеет вероятность 0.
Повторные enum и пустые списки запрещены. Вероятность значения = вес / сумма.
Порядок канонизируется по имени enum. Распределения не влияют на времена,
распространение и выбор сервисов. По умолчанию все три одинаковы:
типы AVAILABILITY, ERROR_RATE, LATENCY, SATURATION с вероятностью 1/4;
severity CRITICAL, WARNING, INFO с вероятностью 1/3.

Шум — однородный пуассоновский процесс с интенсивностью ratePerMinute
**на весь граф**, алерт/мин. Межприходные интервалы −ln(U) × 60000 / rate,
U ∈ (0,1), накапливаются в double-миллисекундах и округляются вниз при записи.
Сервис выбирается равномерно. При rate = 0 шума нет.
Слишком высокая интенсивность, при которой double уже не продвигает время,
приводит к ошибке; ограничения числа событий и молчаливого усечения нет.

## Случайность, ключи и воспроизводимость

У графа, искажения и сценария раздельные seed типа long.
Внутри сценария из scenarioSeed детерминированно выводятся ещё три seed:
failures (выбор корней, открытие дуг, задержки, ключи отказов), noise
(межприходные интервалы, сервисы и ключи шума), signals (все сигналы).
Используется java.util.Random; часов, Math.random и обхода HashMap/HashSet нет.

Вывод seed: mix64(scenarioSeed XOR salt), где salt равен
0x4641494c55524553 для failures, 0x4e4f495345000001 для noise,
0x5349474e414c5301 для signals. mix64(x):
x = (x XOR (x >>> 30)) × 0xbf58476d1ce4e5b9;
x = (x XOR (x >>> 27)) × 0x94d049bb133111eb;
результат x XOR (x >>> 31). Арифметика long с переполнением по модулю 2^64.

Сначала генерируются все отказы (по startedAt, затем id), для каждого алерты
по id сервиса, затем шум. Поэтому изменение интенсивности шума не меняет
полные алерты отказов, включая сигнал и ключ. Изменение весов сигналов не
меняет времена, сервисы, ключи и истину. Обе независимости проверяются тестами.
Внешний ключ — 32 шестнадцатеричных символа из двух nextLong соответствующего
потока failures/noise, при коллизии повторяется выбор. Он не содержит метки.
**Итоговый порядок алертов: occurredAt, затем externalKey при равных временах.**

## Данные и JSON

`GeneratedScenario` содержит formatVersion = 1, modelVersion = "1",
parameters (все входные параметры и три seed), randomSeeds (три выведенных seed),
trueGraph, observation и truth. `observation` содержит только observedGraph
и alerts: `(externalKey, serviceId, occurredAt, signalType, severity)`.
В потоке нет меток отказа. Будущий запуск коррелятора должен передавать только
`ScenarioObservation`, не целый архив эксперимента.

`truth.byAlertKey` отображает каждый ключ ровно в одну метку
`{ "kind": "FAILURE", "failureId": "F1" }` или `{ "kind": "NOISE" }`;
`truth.failures` — список `(id, rootServiceId, startedAt)`.
Метки не добавляются в CorrelationAlert и не видны коррелятору.

JSON UTF-8, порядок полей records фиксирован их объявлением, ключи map
отсортированы, переносы LF,
финальный перевод строки; времена и длительности — ISO-8601 строки.
Дискриминаторы type/kind содержат стабильные имена, не имена Java-классов.
Чтение восстанавливает неизменяемые records и проверяет инварианты;
неизвестные formatVersion/modelVersion отвергаются. Алгоритм или порядок
выборок при изменении модели требует новой modelVersion. Один набор параметров
и seed даёт побайтно одинаковый JSON, включая после чтения и повторной записи.

## Параметры по умолчанию

| Параметр | Единицы / область | Значение |
|---|---|---|
| graph.spec | топология | DEMO |
| graph.seed, distortion.seed, scenarioSeed | long | 42 каждый |
| graph.tier, graph.edgeType | enum, синтетические графы | TIER_2, SYNC |
| missingEdgeRate, spuriousEdgeRate | доля от истинных дуг | 0, 0 |
| spuriousEdgeType | enum | SYNC |
| start | UTC, миллисекунды | 2026-01-01T00:00:00Z |
| injectionPeriod | длительность, > 0 | PT10M |
| failures | режим | SELECTED |
| count | число отказов | 2 |
| firstStartOffset, spacing | длительность | PT0S, PT10S |
| mode | выбор корней | PATH_CONNECTED_TO_FIRST |
| propagationProbability | вероятность [0,1] | 0.8 |
| propagationDelay | миллисекунды, включительно | UNIFORM PT1S…PT5S |
| detection.defaultDistribution | миллисекунды, включительно | UNIFORM PT0S…PT30S |
| detection.overrides | id → распределение | пустой объект |
| noise.ratePerMinute | алерт/мин на граф | 1 |
| signals.root/propagated/noise | веса type и severity | все enum с весом 1 |

Примеры альтернативных топологий: TREE(depth=2, branching=3),
LAYERED(layers=3, width=4, density=0.5), DIAMONDS(count=2, branchDepth=3),
CYCLIC(base=LAYERED(3,4,0.5), reverseEdgeRate=0.25).
Их конфигурации явно содержат те же остальные параметры.

## Известные упрощения

Один алерт на сервис и отказ; нет восстановления, повторных сигналов,
потерь доставки, ограничения ресурсов, воздействия отказов друг на друга
и агрегации пересекающихся сигналов. Вероятность и задержка передачи одинаковы
для всех типов дуг, tier и тип зависимости не влияют на распространение.
Сигналы условно независимы от задержек; шум независим от отказов, сервисы
для него равновероятны. Это параметры синтетической модели, не эмпирическая
модель промышленной системы. Регулярные топологии и связный остов слоистого
графа вносят структурное смещение. Миллисекундная дискретизация создаёт ничьи.
Выбор дополнения искажения требует O(|V|²) памяти; генератор предназначен
для конечных экспериментальных графов, переполнения размеров отвергаются.
Пересборка ранее сформированных групп не моделируется; интерфейс коррелятора
принимает решение при приходе алерта.
